hugframe API reference

The complete public surface of hugframe. For a quick start, see the README.

Everything here is framework-free: plain TypeScript over DOM APIs, no runtime dependencies. The package is ESM-only and browser-only, and it imports nothing.

Package entry points

  1. hugframe — the engine, the <hug-frame> element, the protocol guards and the types.
  2. hugframe/child — the runtime that runs inside the framed document.
  3. hugframe/css — the stylesheet, imported once by the host page.
import { createHugFrame } from 'hugframe'
import 'hugframe/css'

Importing hugframe also registers <hug-frame>, so importing it for the element alone is a legitimate side effect and the package is not marked side-effect free.

createHugFrame(options)

Creates a frame inside container and returns an instance.

function createHugFrame(options: HugFrameOptions): HugFrameInstance

Options

Option Type Default Notes
container HTMLElement — Required. The engine renders its own tree into this element.
src string — Required. The framed document.
title string — Required. Labels the iframe, and names the dialog when expanded.
targetOrigin string current origin Origin expected from the framed document. '*' skips the origin check; the message still has to come from the frame's own window.
initialMode 'inline' | 'expanded' 'inline' The engine owns its mode; a host changes it with expand() / collapse().
height 'content' | number | string 'content' 'content' hugs the framed document; a number is px; any other string is used verbatim, so '60vh' and 'clamp(280px, 45vh, 460px)' both work. Inline only — expanded always fills.
minHeight number 0 Inline-mode floor, px.
maxHeight number 720 Inline-mode ceiling, px.
initialHeight number 240 Inline-mode height before the framed document first reports.

renderCollapse ((handle: HugFrameCollapseHandle) => Node) | null — Replaces the whole expanded-mode control. Receives { collapse }. null hides it, which is how you drive collapsing from your own chrome.
className string — Added to the root element, so --hug-* tokens set here win.
style Partial<CSSStyleDeclaration> — Applied to the root element.
iframeProps Record<string, string | number | boolean | null | undefined> — Attributes applied to the created iframe.
resizeSettleMs number 120 Width quiescence, ms, the resizing phase waits for before settling onto the newly reported height.
resizeSafetyMs number 400 Ceiling, ms, on that wait.
resizeWidthEpsilon number 1 Width change, px, at or below which a layout change is not treated as a resize.
morphSettleMarginMs number 90 Margin, ms, added to the morph duration for the transitionend fallback timer.
expandedWidth string '100vw' Width written on the box once expanded.
expandedHeight string '100dvh' Height written on the box once expanded.
lockScroll boolean true Ref-counted document scroll lock while expanded.
manageFocus boolean true Move focus into the framed document on expand and return it to the previously focused element on collapse.
collapseOnEscape boolean true Escape in the host document collapses the frame. A framed document that handles Escape itself and calls requestCollapse() is making an explicit request rather than pressing this shortcut, so it is honoured either way.
onModeChange (mode: HugFrameMode) => void — Fires on every mode change, including ones the framed document requested.
onPhaseChange (phase: HugFramePhase) => void — Fires on phase transitions only, not on every frame.
onSizingChange (sizing: HugFrameSizing) => void — Fires when the sizing mode actually changes.
onReady () => void — The framed document has loaded and announced itself with ready.
onRequestClose () => void — The framed document asked to be closed. Unmounting is the host's decision; the engine never removes itself.
onMessage (payload: unknown) => void — Arbitrary payload sent from the framed document with sendMessage().

Instance

Member Type Notes
element HTMLElement (read-only) The root the engine rendered.

collapse() void Returns to the inline slot.
toggle() void Whichever of the two applies.
sendMessage(payload) void Posts a custom message to the framed document.
update(next) void Merges the options and re-applies what depends on them, without remounting the frame. Phases

idle is the resting state. expanding and collapsing are the morph. resizing is entered when the embedding layout changes the frame's width underneath it — the engine suspends content chasing, holds the height so the framed document clips rather than jumps, and settles onto the newly reported height after 120ms of width quiescence, or 400ms at the latest. Both waits are configurable with resizeSettleMs and resizeSafetyMs. With prefers-reduced-motion: reduce the phase is skipped entirely and heights are applied instantly.

<hug-frame>

The same engine as an element. Register it by importing the package.

<hug-frame src="/embedded.html" title="Embedded app" height="content"></hug-frame>
<script type="module">
  import 'hugframe'

  const el = document.querySelector('hug-frame')
  el.expand()
</script>

Properties

collapseIcon (Node | string), renderCollapse (((handle) => Node) | null) and iframeProps — the options that cannot be expressed as attributes. There is deliberately no collapse-icon attribute: a glyph is a Node or a string, and the element takes it as a property.

The behaviour switches lockScroll, manageFocus and collapseOnEscape are properties too, defaulting to true. A boolean attribute's absence-versus-false semantics is a trap, so there are no corresponding attributes. Every numeric and string knob above — resizeSettleMs, resizeSafetyMs, resizeWidthEpsilon, morphSettleMarginMs, expandedWidth and expandedHeight — is attribute-backed and also readable and writable as a property of the same name.

Methods

The instance methods above, plus destroy(). connectedCallback creates the engine and disconnectedCallback tears it down, but teardown is deferred by a microtask so that moving the element within the DOM relocates it instead of rebuilding it.

createHugFrameChild(options)

Import from the hugframe/child subpath, and call it inside the framed document.

function createHugFrameChild(options?: HugFrameChildOptions): HugFrameChild
function getHugFrameChild(): HugFrameChild | undefined

Options

Option Type Default Notes
targetOrigin string '*' Origin expected from the host. The parent window is required whatever this is.
sizeSelector string document.documentElement Element whose box height drives the frame.
offsetHeight number 0 Constant px added to every reported height.
reportEpsilon number 0.5 Px deadband below which a measured size change is not reported.
onMessage (payload: unknown) => void — Arbitrary payload sent from the host.
onModeChange (mode: HugFrameMode) => void — The host entered inline or expanded.
onSizingChange (sizing: HugFrameSizing) => void — The host started driving the height, or went back to content.

targetOrigin defaults differently on the two sides: the host defaults to its own origin, because it knows where it serves its framed document from, while the framed document defaults to '*', because it cannot know which host embedded it. The wildcard relaxes the origin check only — the framed document always requires event.source to be its parent window.

Instance

isFramed, mode and sizing are read-only. Methods: resize(), suspend(), resume(), requestExpand(), requestCollapse(), requestClose(), sendMessage(payload), destroy().

The runtime is a safe no-op when the document is opened outside a frame, so a framed app can also be previewed directly. It warns once through console.warn when two consecutive size reports equal the frame's own height, the signature of a document laid out at height: 100vh.

Attributes the runtime writes

data-hug-sizing — content or fixed — on the framed document's root element, for the framed document's own CSS. Keying overflow off data-hug-sizing="fixed" is what lets a host-driven height scroll internally, while content sizing clips the single frame between content growth and the height report arriving.

The wire protocol

Every message is a plain JSON-serializable object carrying source: 'hugframe', and every message is validated by an exported guard.

Framed document to host

Message Shape
ready { source, type: 'ready' }
size { source, type: 'size', height: number, width: number }
request { source, type: 'request', action: 'expand' | 'collapse' | 'close' }
custom { source, type: 'custom', payload: unknown }

Host to framed document

Message Shape
mode { source, type: 'mode', mode: 'inline' | 'expanded' }
sizing { source, type: 'sizing', sizing: 'content' | 'fixed' }
custom { source, type: 'custom', payload: unknown }

Exported helpers

HUGFRAME_SOURCE (the string 'hugframe'), HUGFRAME_Z_INDEX, isHugFrameChildMessage(value), isHugFrameParentMessage(value) and postHugFrameMessage(target, message, targetOrigin).

Two checks matter and both are enforced. The host verifies that event.source is the frame's own contentWindow as well as the origin, and the framed document verifies that event.source is its parent window as well as the origin. The parent check holds even when targetOrigin is '*', so the wildcard widens which origins are accepted, not which windows. Trusting the source field inside the payload alone would be a security regression.

Appearance: parts, state attributes and the layered stylesheet

The appearance API is three things: the four colour custom properties, the three engine-coupled custom properties, and the stable data-hug-part hooks on every element the engine generates. The stylesheet ships as two sheets behind three import paths: hugframe-core.css holds the geometry and the animation the frame needs to work, hugframe-theme.css holds the default chrome, and hugframe/css imports both. Every other visual value is a plain literal in the rule that already used it, in the theme sheet, and both sheets are wrapped in @layer hugframe. The framed box is one of those literals: it ships square — border-radius: 0 on [data-hug-part='box'] — so a rounded frame is the host's to set, as the demo does with 14px.

Stylesheet entry points

  1. hugframe/css — the default. Imports the two sheets below, core first, and contains nothing but those two imports, so it keeps working exactly as before.
  2. hugframe/css/core — only the mechanism and the animation: the content-hugging geometry, the transitions keyed off data-phase, the iframe reset and the placement of the collapse slot. It has no paint of its own — no colours, surface, scrim or focus ring — so import it when you want to own the look and style the frame against the documented parts.
  3. hugframe/css/theme — only the default appearance: the four colour tokens and their light/dark pair, the box's surface and hairline, the backdrop scrim, the collapse control and the focus outlines. Import it on its own when you already load the core mechanism, or to extend the palette without rewriting the chrome.

Replacing the look means importing hugframe/css/core and writing the visuals — the 40px pill, the 18px glyph, the box's border-radius: 0, the focus offsets — against the parts below. Those literals live in the theme sheet precisely so it is the only sheet you drop.

Custom properties

Set them on the root element — directly, or through className/style.

Token Default Sheet Kept because
--hug-z-index 1000000000 core The engine reads it in getZIndex(), and the exported HUGFRAME_Z_INDEX must match it. Kept to few significant digits deliberately: CSS minifiers, including the Lightning CSS that Vite builds with, round longer numeric literals, which would silently disagree with the export.
--hug-initial-height 240px none The engine writes it on every height update, before the framed document first reports; the box's fallback in the core sheet must equal the value it writes.
--hug-duration 460ms core The engine reads it to size the morph's transitionend fallback, and the morph transitions read it too, so one value drives both.
--hug-surface light #ffffff / dark #171a20 theme The frame's own background, so a box that is momentarily larger than the frame never shows the page through it.
--hug-text light #14171f / dark #ececea theme The frame's text colour, and the collapse glyph through currentColor.
--hug-line light #dfe3ea / dark #2b2f38 theme Hairline borders and dividers.
--hug-accent light #4b46e0 / dark #9b94ff theme The focus ring.

The four colour tokens carry a library-owned light/dark pair and are the documented colour path; the theme sheet declares them, and a host that owns its own theme — MUI, a manual light/dark toggle — should set all four rather than one. The other three are coupled to the engine: --hug-z-index and --hug-duration are declared by the core sheet, and --hug-initial-height is written by the engine itself. These seven are the entire token surface.

Parts

Every element the engine generates carries a data-hug-part attribute. It is the documented selector contract; the .hug-* classes remain on the same nodes, but new CSS should key off the part.

Part Element
root The outer element the engine renders.
backdrop The scrim behind the expanded frame.
box The clipped box that holds the frame.
frame The <iframe>.
collapse The library-owned slot that positions the expanded-mode control.
collapse-icon The built-in collapse glyph.

The node inside the collapse slot is not the library's: it is the built-in button, or whatever renderCollapse returned (and nothing at all for renderCollapse: null). The slot owns where the control sits; the node owns what it is.

State attributes sit on the root and are the other half of the contract: data-mode (inline / expanded), data-phase (idle / expanding / collapsing / resizing), data-sizing (content / fixed) and data-ready. The framed document receives data-hug-sizing on its own root.

@layer and overriding

The whole stylesheet ships inside @layer hugframe { … }, declared by each part sheet. The combined hugframe/css imports them with a plain @import, not @import … layer(hugframe): wrapping again would nest the layer as hugframe.hugframe and change its priority against an unlayered consumer rule. An unlayered consumer rule therefore beats it whatever its specificity, so a consumer can override the expanded state with a plain rule and no !important: a .hug-box { … } in your own stylesheet wins over the library's .hug-root[data-mode='expanded'] .hug-box.

Example: restyling the collapse control

The slot keeps the control's position; restyle the node inside it with ordinary, unlayered CSS:

/* your stylesheet */
[data-hug-part='collapse'] .hug-collapse {
  width: 32px;
  height: 32px;
  border-radius: 8px;
  background: #111;
  color: #fff;
}

What can and cannot be hugged

Hugging needs the framed document's height, and the engine has exactly one source for it: the size message. Every case below follows from that, in three tiers.

  1. Content you control hugs. Same-origin pages, srcdoc, and anything you serve yourself: import createHugFrameChild from hugframe/child inside the framed document, as above. A cross-origin page you control hugs the same way, by including that runtime; it is the library's headline capability.
  2. A third-party page you cannot modify cannot be hugged. The parent has no layout information about a cross-origin document: the same-origin policy makes iframe.contentDocument throw, no API exposes the inner document's size, the framed page must run something to answer postMessage, and CORS blocks fetching another origin's HTML. Give the frame a deliberate height instead — height: 480, or any CSS string, used verbatim, so 'clamp(280px, 45vh, 460px)' works — or proxy the page onto your own origin and treat it as the first tier, at the cost of relative URLs, CSP, cookies and the other site's terms of service.
  3. A document sized to its own viewport has no intrinsic height to converge on. A document using 100vh, or a height: 100% chain, measures the frame it sits in and reports that height back, so the frame never hugs anything. It is the loop the runtime warns about once, under the layout rules below. Let the host dictate the height instead, through the child's data-hug-sizing attribute and its suspend() and resume() methods, rather than a content report.

Without a report the frame uses initialHeight, 240px by default, clamped by maxHeight. Growing the frame until the inner scrollbar disappears is not an alternative: reading that scrollbar needs the same blocked access that measuring the document needs, so it only works where direct measurement already works, and it is the scrollbar feedback loop itself — a scrollbar takes width, the content reflows taller, the frame grows, the scrollbar goes away, the content shrinks — which browsers mitigate with scrollbar-gutter: stable. Where the frame is measurable, one scrollHeight read is both correct and cheaper.

Layout rules for credible framing

  1. Never use vh/dvh/vw on the axis the host controls while content-sized. A min-height: 100vh in inline mode makes the frame report the viewport height, the host grows the frame, and the content grows again — a resize loop. The framed document's runtime warns once when two consecutive size reports equal the frame's own height, which is that loop's signature.
  2. Do not give the framed document's html or body a height: 100%.
  3. Use container queries, not media queries, inside the framed document: its width has nothing to do with the viewport.

Constraints worth knowing

  1. The framed document is never remounted by a mode change, so its state survives the morph. Moving the frame in the DOM is different: that detaches and re-inserts it, and the browser destroys the iframe's browsing context, so the framed document reloads. The same iframe node and engine survive and re-sync on the next ready, but genuine state preservation across a move needs Element.moveBefore().
  2. The expanded view locks document scrolling while it is open, and the lock is ref-counted across frames. lockScroll: false opts a frame out.
  3. Escape collapses, focus moves into the framed document on expand and returns to the element that was focused before it, and the expanded box carries role="dialog" with aria-modal. The first two are switchable with collapseOnEscape and manageFocus; the dialog semantics are not, and are an accessibility contract rather than a preference.
